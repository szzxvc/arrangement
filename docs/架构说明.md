# 架构与事务说明

## 运行结构

浏览器通过同一站点读取前端静态文件并调用 `/api/*`。Wrangler 优先把 `/api` 和 `/api/*` 交给 Hono Worker，其他路径使用 Static Assets 的 SPA 回退。未知接口保持 JSON 响应；页面深链接刷新得到 `index.html`。

开发时 Vite 5173 代理 API 到 Wrangler 8787；发布时所有前端文件在 `dist/`，后端入口为 `worker/index.ts`，无需另一个前端服务器。数据库只有 D1，不使用内存锁、读副本、Redis 或额外服务器。

## 数据模型与约束

| 表 | 内容与主要约束 |
| --- | --- |
| `users` | 不可变用户 UUID、展示名、唯一规范化名、scrypt 算法参数、盐和派生结果 |
| `sessions` | 随机会话令牌 SHA-256 摘要、用户、CSRF 令牌、七天到期时间 |
| `auth_rate_limits` | 来源地址／规范化账号的摘要桶、十分钟窗口和累计次数 |
| `projects` | 名称、描述、创建人、创建时间 |
| `project_members` | 项目和用户联合主键、加入时间、状态版本；不另存工作状态 |
| `project_invitations` | 邀请人、被邀请人、待处理／接受／拒绝状态；同项目同目标最多一条 pending |
| `work_sessions` | 实际工作者、时间、开始／结束操作人和原因、操作 UUID；每项目最多一条未结束记录 |
| `reservations` | 项目、预约者、整分钟起止、active／cancelled、取消时间和操作标识 |
| `audit_events` | 实际状态变化的操作人、目标、工作记录、原因和时间 |
| `mutation_requests` | 用户和请求标识联合主键、规范请求指纹、成功结果、事务守卫 |

表关联一律采用不可变用户 ID。成员与工作、预约、操作人的关系受复合外键约束。预约时间顺序和精度受 CHECK 约束。

时间全部保存为 UTC 整数秒，展示和日期输入固定加 UTC+8。无时区输入先检查格式和真实日期，再明确计算偏移；不会依赖浏览器默认时区。接口只接收预约时间，不接收实际打卡时间。

## 实际工作原子性

`one_active_worker_per_project` 是 `work_sessions(project_id)` 的部分唯一索引，仅对 `ended_at IS NULL` 生效。无论普通开始还是强制开始，插入都经过相同约束。20 人同时提交也只能有一条成功。

工作插入触发 `audit_work_start`，结束转换触发 `audit_work_stop`。触发器在主变更同一个数据库事务中写审计并递增成员状态版本。失败或零行 UPDATE 不会触发虚假状态变化。

结束操作条件包含项目、目标用户、当前工作 UUID、尚未结束；普通结束目标被限定为当前登录用户。旧工作 UUID 即使与下一次工作属于同一人，也不会结束新工作。

强制操作发送明确 `state`、`expectedState`、`expectedWorkSessionId` 和 `expectedVersion`。事务中核对成员版本和记录条件。不采用 toggle，也不默认抢占。状态从休息变干活再回休息后，版本也会增加，旧休息状态确认同样过期。

## 幂等与事务守卫

所有项目、邀请、工作、预约业务变更要求 `X-Request-ID`。服务端将方法、站内路径和排序后的 JSON 请求体生成 SHA-256 指纹。用户与标识联合唯一，同标识配不同指纹返回 409。

每次新变更的 D1 `batch()` 首先写入成功结果记录，再执行业务 SQL。整个批次是一个事务，因此结果不会先于真实成功独立提交；失败后两者一起回滚。并发同标识的第二个批次在唯一约束处失败，再读取第一个已提交结果。

结果重放前仍进行会话、项目成员和目标所有权检查。登录账号改变后不能读取其他用户的幂等结果。没有将令牌或密码存入幂等结果。

SQL 条件 UPDATE 可能影响零行而不报错。对这种操作使用 `mutation_requests.guard` 的命名 CHECK 约束作为事务守卫：条件成立写 1，不成立尝试写 0，从而抛错并回滚整个批次。审计依赖真实变化，加入成员仅选择本次操作 UUID 已接受的邀请，不会因旧邀请或零行更新误加入。

幂等结果在第一版持续保留，支持长期重试。自动清理这些记录会改变重试语义，应在之后的留存方案中明确窗口，而不是直接定时删除。

认证注册通过用户名唯一约束防重复；登录产生新会话，退出撤销当前会话。认证接口不缓存含 Cookie 的业务结果，避免保存原始会话令牌。

## 预约原子性

`reservation_overlap_insert` 和 `reservation_overlap_update` 触发器保护有效预约。重叠条件是同项目、active 状态、`new.start < old.end && new.end > old.start`。更新排除自身 UUID，覆盖时段、项目和状态恢复路径。

取消只允许当前用户的指定预约。真实取消与幂等结果同批次提交；记录保留，时段立即释放。过去预约以时间动态推导，不运行改变实际工作状态的定时任务。

前端预约弹窗既展示近期安排，又用所选起止范围查询全部有效冲突；提交前提示冲突，数据库继续承担过期页面和并发提交的最终约束。

## 认证与边界

- `scryptSync` 来自 Workers 的 `node:crypto`，N=16384、r=8、p=5，16 字节随机盐，64 字节结果，恒定时间比较。
- 不透明 Cookie 令牌 32 字节随机数，数据库存摘要；HttpOnly、SameSite=Lax，生产强制 Secure。
- 注册／登录在昂贵密码派生前更新持久限流桶：账号 10 次／10 分钟，地址 40 次／10 分钟。
- 变更请求检查精确同源 Origin；开发代理只允许明确配置的本地来源；已登录变更另需当前会话的 CSRF 令牌。
- 未登录返回 401，非项目成员返回 404；待处理邀请不提供成员资格。
- JSON 请求体限制为 16 KiB；所有 SQL 使用参数绑定，错误不回传底层数据库细节。
- 私有 API 禁止缓存；生产 Static Assets 带 CSP、禁止嵌入及 MIME 嗅探的安全头。

用户名注册仍开放，没有社团邀请码或全局管理员。项目私有不等于账号注册受邀。如将来需要封闭注册，应新增明确业务规则。

## 同步与界面

项目快照用 D1 `batch()` 在一致读取中返回项目、全部成员及活动工作记录、首屏预约、最近审计和服务端时间。避免每成员请求。

前端每五秒读取，隐藏时中止请求并暂停轮询，恢复可见、获得焦点或联网立即读取。轮询请求不重叠；操作后的刷新取消旧读取，序号防止旧响应覆盖最新状态。页面按服务端时间差更新持续时间和北京时间“今天”。

界面成功状态只在服务端成功响应后更新，网络断开时提示结果未确认。网络失败自动重试一次并复用请求标识；相同操作再次提交继续复用未确认标识。弹窗使用原生 `dialog` 的焦点管理和键盘取消，过期状态要求关闭后重新确认。

## 运行基线与后续边界

兼容日期固定 `2026-04-26`，启用 `nodejs_compat`。依赖版本和完整锁文件已实际安装、构建、测试。

Workers Paid 是默认配置的基线，CPU 上限 30 秒。另有不设置 CPU 上限的 Free 试部署配置。云端试部署测得认证 CPU 为 181–194 毫秒，超过 Free 的标称 10 毫秒额度；完整功能验收已通过，免费稳定性尚未证明。峰值内存、大规模成员数、认证峰值、长期历史和幂等结果需进一步做容量与压力设计，详见验证记录。

本版没有生产默认账号，测试账号仅存在隔离测试数据库。部署不会自动把本地账号或测试记录迁入云端。
